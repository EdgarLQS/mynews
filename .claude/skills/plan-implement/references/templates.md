## 实施说明

```text
从最新 <基线> 创建并切换分支 <codex/分支名>，允许/不允许修改和提交。
先检查工作目录、Git 状态、docs/README.md、功能矩阵和唯一 Current 计划，保护已有变更。

目标：<一句话目标>
范围：<模块、CLI、JSON、文档、测试>
非目标：<明确不做的内容>
接口与兼容：<公共命令/字段/Schema/模块 seam>
文档同步：<计划、架构、ADR、矩阵、README、AI 入口>
验收准备：<离线门禁、真实网络/Codex/回溯要求>
禁止：不得伪造 Verified、绕过访问控制、操作真实 launchd 或污染 output/state/logs。

完成后报告实际命令、退出码、测试结果、剩余风险，并按约定提交。
```

## 实施验收说明

```text
阶段 A：只读首轮验收
验收 <目标分支>，以其与 main 的 merge-base 为基线，覆盖全部提交、未提交和未跟踪文件。
本阶段不得修改、格式化、修复、暂存、提交、切换分支或污染 output/state/logs；不得操作真实 launchd。

检查：
1. 文档状态、唯一 Current 计划、归档关系和 diff check。
2. Ruff、Mypy、受影响测试、全量测试和中文 CLI help。
3. JSON Schema、兼容规则、失败恢复、状态机、第一方证据门槛和退出码。
4. 真实来源、生产 Codex、隔离运行或定时能力；只用 mock 或外部阻断不得 PASS。

报告按“计划、执行、验证”，先列问题、文件和证据，再给 PASS、PASS_WITH_LIMITATIONS、BLOCKED 或 FAIL。
未执行项标记 SKIPPED 并说明原因；不修复问题。

阶段 B：独立修复
仅针对阶段 A 已确认的问题修改代码或文档；保留无关工作树变更，补充回归测试，报告实际修改和命令结果。

阶段 C：修复后复验
重新执行阶段 A 的受影响门禁和全量门禁；确认所有问题已关闭、没有新回归后，才可给最终 PASS。
```
