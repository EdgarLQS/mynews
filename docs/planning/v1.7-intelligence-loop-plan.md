# mynews v1.7 分时情报分析与人工反馈闭环计划

## 基线与目标

本计划以已包含 v1.6 全部交付的最新 `main` 提交 `1173719` 为规划基线。实施时必须
重新确认最新 `main` 仍包含该提交，再创建 `codex/v1.7-intelligence-loop` 分支；不得
从 v1.6 或更早的功能分支续做。

P0–P4 已合入本地 `main` 提交 `e60c0c7`。P5 真实验收以该提交为固定代码基线；开始前
仍须确认最新 `main` 包含该提交、工作树干净且没有新的替代计划。P5 不是来源开发阶段，
不要求先推送远端；真实任务只在固定版本的持久化隔离 worktree 中运行。若 `main` 已变化
或无法确认固定基线，停止并重新核对，不从旧的 v1.7 功能分支继续工作。

v1.6 已完成 newsFromAI `datacollection` 的功能吸收。v1.7 P0–P4 已完成离线实现；P5
真实双档、latest-only 补跑和失败恢复仍需独立授权验收。v1.7 不新增来源、不改变
SourcePlugin、Candidate Contract、Digest Schema 或 `verified` 门槛，而是吸收
`newsFromAI/news-task.md` 和编辑流程中适合 mynews 的部分：09:00/18:00 分时分析、
latest-only 补跑、增量事件去重、四问式结论、中国 AI 单列，以及经作者确认后的发布
台账和周反馈回填。

## 范围与非目标

本阶段交付：

- 根目录 `news-task.md`，作为 Codex 分时情报任务的唯一操作规范；
- 09:00 和 18:00 两个 `Asia/Shanghai` 档位，错过多个档位时只执行最新档；
- 0–6 条正式情报、待核查线索、重要更新、跳过原因和运行警告；
- 原子报告和任务状态，失败不得推进成功档位；
- `mynews publication add` 和 `mynews feedback record` 两个确定性人工回填命令；
- 对应文档、项目技能、测试和分阶段验收说明。

明确不做：

- 不新增或替换来源，不把人工清单、Candidate 摘要或 discovery 写成 `verified`；
- 不新增核心 Briefing 模型或修改 Digest Schema；分析由 Codex 任务文档驱动；
- 不自动发布，不生成 PPT、小红书图片、Canva、TTS 或视频；
- 不复制 SQLite，不新增生产依赖，不自动注册 Codex 任务或操作真实 launchd。

## Codex 分时任务契约

根目录 `news-task.md` 使用固定元数据：`schema_version=1`、`enabled=true`、
`timezone=Asia/Shanghai`、档位 `09:00`/`18:00`、`catch_up=latest_only`、中文输出，
每档最多 6 条且允许为 0。任务必须按下列顺序使用既有公开接口：

1. `uv run mynews prepare --date YYYY-MM-DD --refresh` 刷新候选和人工清单；
2. `scripts/collect-expanded.sh --days 2` 运行 built-in 与显式扩展来源及生产核验；
3. `uv run mynews validate --run output/latest.json --check-evidence` 复核已保存证据；
4. `uv run mynews digest --run output/latest.json --out-dir output` 生成严格 Digest；
5. 读取 Digest、上一档报告、任务状态、publication ledger 和 weekly feedback，生成本档报告。

`prepare` 或 collect 返回 `3 (partial)` 时，只有必要输出完整且失败已结构化记录才可继续，
并在报告中保留警告；返回 `1/2` 或证据校验失败时必须停止，不覆盖已有报告。正式情报只能
来自 Digest `main_items` 的 `verified` 条目；Candidate、人工清单和 `lead_items` 只能进入
“待核查线索”。真实内容不足时明确写“本轮暂无重要更新”，不得用旧闻或弱证据补足数量。

正式条目必须回答：发生了什么、影响谁、为什么重要、现在是否需要行动，并附已保存的
第一方证据。中国 AI 单列但计入总数，不设强制配额；争议事项只有单一官方来源时明确标注。
已报告或已发布事件默认跳过，只有功能、价格、可用范围、日期、迁移要求、风险或限制发生
实质变化时才作为重要更新再次报告。

## 输出与状态契约

每档报告写入：

```text
output/editorial/automation/reports/YYYY-MM-DD-HHmm.md
```

任务状态写入：

```text
state/editorial/automation/state.json
```

状态固定包含 `schemaVersion`、`lastAttemptAt`、`lastSuccessAt`、
`lastCompletedSlot`、`lastReport` 和 `reportedEvents`。每个 reported event 只保存事件键、
上次报告时间、内容哈希和报告相对路径，不保存密钥、Cookie、授权头或个人绝对路径。
报告必须先通过同目录临时文件、`flush`、`fsync` 和 `os.replace` 完成，再更新状态；状态
写入失败不得把档位标成成功。任务不得修改 publication ledger 或 weekly feedback。

## 人工回填 CLI 契约

### `mynews publication add`

必填参数为 Candidate 文件、一个或多个 event ID、发布标题、平台、公开 HTTPS 链接和带时区
的实际发布时间。event ID 必须匹配 Candidate 的 `duplicateGroupId`，缺失时才允许匹配
`candidateRef`/`id`；无法匹配、缺少链接或时间时拒绝写入，不写占位行。同一
event ID、平台和链接的重复记录幂等无变化；一篇内容包含多个事件时，为每个事件分别写行，
允许共用标题、平台、链接和时间。

默认写入 `output/editorial/publication-ledger.csv`，并允许显式输出路径供隔离测试使用。
成功输出机器可读的 `created`/`unchanged` 状态；运行失败退出 `1`，参数错误退出 `2`。

### `mynews feedback record`

必填参数为 ISO 周、平台以及非负的阅读、收藏、转发、新增关注数；典型反馈为可选单行文本。
默认写入 `output/editorial/weekly-feedback.md` 的稳定标记区块。同一周和平台的相同内容幂等
无变化；不同内容默认冲突失败，只有显式 `--replace` 才替换对应区块。输出和退出码与
publication 命令一致。

两个命令都必须复用可分享输出隐私门禁，使用原子写入，异常不得回显敏感值、覆盖旧文件或
遗留 `.tmp`。它们只记录作者明确提供的事实，不发布内容、不访问网络、不调用 Codex，且
不得修改 Candidate、RunReport、Digest、Store 或 `verified`。

## P5 真实任务验收执行计划

### 授权、基线与隔离

- 用户批准本计划只代表计划确认；只有用户再次明确要求“开始 P5 真实验收”时，才允许
  创建或启用 Scheduled Task、执行真实网络 probe 和故障恢复演练。
- 以 `e60c0c7` 为固定代码基线创建持久化 detached worktree，并记录绝对路径、提交、创建
  时间和 Git 状态。验收任务只能写该目录的 `output/`、`state/` 和 `logs/`；不得修改或
  提交源码、测试、文档、Git 元数据、publication ledger 和 weekly feedback。
- 验收前记录隔离目录中 publication ledger、weekly feedback 和全部已跟踪文件的校验值；
  验收后复核它们不变。运行证据保存到隔离目录的 `logs/p5/`，不得提交或包含秘密。
- 不安装、不调用也不修改旧的 09:30 launchd；`scripts/collect.sh install` 不属于本阶段。
  开始前检查同名 Scheduled Task，存在时优先核对和复用，不创建重复任务。
- Scheduled Task 使用桌面应用的本地项目能力，目标为上述隔离目录。根据 OpenAI Docs，
  本地任务运行时电脑和桌面应用必须保持运行，任务使用无人值守的默认 sandbox；因此只
  开放完成采集所需的工作区写入、网络和明确命令，不启用无边界全盘权限。参考：
  [Scheduled tasks](https://learn.chatgpt.com/docs/automations)（访问于 2026-08-20）。

### P5-A 只读首验与环境预检

1. 记录 `pwd`、固定提交、分支、工作树、Python/uv 版本、Codex 任务能力和当前自动任务清单；
   首验不得改源码、文档、任务配置或运行台账。
2. 执行文档检查、`git diff --check`、Ruff、Mypy、v1.7 相关测试、全量测试和中文 CLI help；
   任一程序门禁失败记为 `FAIL`，外部权限或服务不可用记为 `BLOCKED`，不得边验边修。
3. `plugin list` 只用于确认 entry-point 元数据，`loaded=false` 不代表工厂或网络可用。逐一
   执行下列 15 个插件的真实 `probe --plugin`，记录时间、安装状态、来源状态、抓取数、
   接受数和限制：

   - primary：`openai-news`、`google-blog`、`github-changelog`、`hugging-face-blog`、
     `google-deepmind`、`nvidia-ai`、`aws-machine-learning`；
   - research：`kimi-k2-releases`、`glm-releases`；
   - incident：`deepseek-status`、`openai-status`、`anthropic-status`、`github-status`；
   - discovery：`techcrunch-ai`，只能发现线索；
   - benchmark/manual：`paperswithcode-daily`，预期结构化为 `manual/blocked`，不得请求猜测
     的 Feed，也不得用 fixture 或其他来源代替。

4. primary、research 和 incident 仍须经过程序证据核验才能进入正式情报；discovery、manual
   和搜索摘要不能单独把条目标为 `verified`。合法空 Feed、实验来源 blocked 和人工入口必须
   如实保留，不能静默降级或借其他来源补齐。

### P5-B 同权限手动彩排

在注册定时任务前，使用将来任务相同的隔离目录、sandbox、网络边界和任务提示手动执行一次。
固定顺序为：

1. `uv run mynews prepare --date YYYY-MM-DD --refresh`；
2. `scripts/collect-expanded.sh --days 2`；
3. `uv run mynews validate --run output/latest.json --check-evidence`；
4. `uv run mynews digest --run output/latest.json --out-dir output`；
5. 依据 `news-task.md` 生成报告，再原子更新任务状态。

返回 `3 (partial)` 时，只有必要输出完整且结构化失败已保留才可继续；返回 `1/2`、证据校验
失败、输出缺失或状态损坏时立即停止。彩排必须证明提示、工具和权限可用，但不能替代真实
09:00/18:00、漏档补跑或失败恢复证据。

### P5-C Scheduled Task 注册与观察

- 使用一个项目级独立 Scheduled Task，目标为固定版本隔离目录，时区和档位严格保持
  `Asia/Shanghai`、09:00/18:00，执行契约只引用根目录 `news-task.md`，不复制另一份流程。
- 注册前先在普通任务中完成 P5-B，注册后检查任务为预期状态、下次运行时间正确、没有重复
  任务。运行期间保持电脑开机、桌面应用运行、隔离目录可访问。
- 逐次保存任务 run 标识、开始/结束时间、业务日期、档位、最终状态、退出码、报告路径与
  哈希、状态关键字段、RunReport/Digest 路径与哈希、来源失败以及脱敏警告。
- 验收完成后的任务最终状态必须在报告中写明。若用户未单独确认长期保留，完成取证后默认
  暂停任务，避免把一次验收授权扩大成长期无人值守运行授权。

### P5-D 真实场景与成功判定

| 场景 | 执行与证据 | 成功条件 |
| --- | --- | --- |
| 09:00 档 | 等待真实档位自动运行，保存任务 run、报告、状态和 Digest 对照 | 生成 `YYYY-MM-DD-0900.md`；状态指向该报告；正式情报 0–6 条且只来自 verified `main_items` |
| 18:00 档 | 等待真实档位自动运行，保存与 09:00 相同的证据 | 生成 `YYYY-MM-DD-1800.md`；状态推进到 18:00；重复和重要更新规则正确 |
| latest-only | 让任务跨过至少两个应处理档位未运行，再恢复到当前最新档位 | 只执行恢复时应处理的最新档；较早漏档没有补写报告或推进记录 |
| 前置失败保护 | 在隔离状态中注入可恢复的非法状态，运行后恢复备份 | 任务失败；旧报告和成功档位不被覆盖；只允许 `lastAttemptAt` 按契约变化；无 `.tmp` |
| 报告先于状态 | 保持报告目录可写，受控阻断状态目录写入，再恢复权限 | 报告先原子落盘；状态不标成功且不产生悬空成功引用；无秘密和 `.tmp` |
| 恢复运行 | 清除受控故障后再次执行同一最新档 | 成功报告和状态一致；不会丢失历史 run，也不把失败伪装成成功 |

每个正式条目必须能反查到本轮 Digest 的 verified `main_items`、已保存第一方 URL 和摘录；
Candidate、manual、discovery 与 `lead_items` 只能出现在待核查线索。无可靠更新时允许 0 条并
明确写“本轮暂无重要更新”。每个场景结束后还要确认：

- `lastReport` 使用相对路径且目标存在，报告修改时间不晚于成功状态提交时间；
- `lastCompletedSlot`、`lastSuccessAt`、`reportedEvents` 与实际档位一致且不含敏感字段；
- publication ledger、weekly feedback、源码、文档和 Git 状态未被任务修改；
- 运行目录之外没有新增文件，运行目录内没有残留 `.tmp`；
- 报告先于状态的精确故障恢复继续由离线注入测试提供程序级旁证，真实运行不得只靠 mock。

### P5-E 结论、修复与状态回写

- 09:00、18:00、latest-only、前置失败保护、报告先于状态和恢复运行全部通过，且 G6-V/G7
  没有未解释的必需项跳过，P5 才能给 `PASS`。外部网络、Codex、sandbox、管理员策略或调度
  环境阻断时给 `BLOCKED`；程序或契约错误给 `FAIL`。
- `FAIL` 后暂停真实任务，不在验收目录修源码。从最新 `main` 创建新的
  `codex/v1.7-p5-fix` 分支，按“只读首验、独立修复、完整复验”处理；修复提交合入最新
  `main` 后，重新建立固定基线和隔离目录，失败证据不能沿用为成功证据。
- `PASS` 后从最新 `main` 创建 `codex/v1.7-p5-verification` 文档分支，只回写有真实证据的
  `AI-02`、`DATA-07`、`OPS-04` 及与其一致的计划、规划索引和 docs 总览状态；其他功能不得
  顺带上调。记录日期、固定提交、命令、任务 run、脱敏结果和剩余限制，不提交运行产物。
- 文档回写执行 `python3 scripts/check_docs.py`、`git diff --check` 和治理状态检查，通过后才
  允许 fast-forward 合入本地 `main`；不自动 push。v1.7 收口后的新需求必须从当时最新
  `main` 创建新的 `codex/<phase>` 分支，不再从任何 v1.7 分支继续开发。

## 验收门槛

首轮只读，以目标分支与 `main` 的 merge-base 为基线，覆盖提交、未提交和未跟踪文件。
执行 G0、G1、G1-S、G2、G3、G4、G5；真实分时 Codex 任务增加 G6-V 和 G7。修复必须在
首轮报告后作为独立步骤进行，修复后重新执行受影响门禁和完整复验。

必须验证：

1. 仓库中只有一个 Current 计划；v1.6 归档原文和真实限制完整保留。
2. task 元数据、双档/latest-only、0–6 条、partial/failed 处理和状态推进规则可静态复核。
3. 正式情报只来自 verified main items；线索、manual 和 Candidate 不能越过事实边界。
4. publication 的 Candidate ID、重复、多事件、缺失字段和旧 ledger 读取兼容通过。
5. feedback 的指标、幂等、冲突、`--replace` 和 Markdown 稳定区块通过。
6. 两个命令均无网络/Store/Codex 副作用，敏感值不回显，失败恢复旧文件。
7. `prepare`、collect、validate、digest、plugin-only、追加扩展和 watchlist 无回归。
8. 实际执行文档检查、diff check、Ruff、Mypy、相关测试、全量测试和中文 CLI help。

离线门禁通过最高标记 `Implemented`。只有在用户明确授权的真实 Codex 任务中完成两个
档位、latest-only 补跑和失败恢复后，才可把分时任务标为 `Verified`；未注册或外部环境
受限必须写 `SKIPPED`/`BLOCKED`，不得用任务文档或 mock 代替。
