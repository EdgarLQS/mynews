# v1.1 信息质量闭环与可读报告计划

## 目标与边界

v1.1 在已完成的 v1 来源采集、第一方核验和 JSON Store 之上，补齐“来源健康可解释、候选可筛选、核验可追踪、结果可阅读”的离线闭环。所有新字段采用 JSON minor 兼容方式增加；现有 `1.0` RunReport fixture 继续可读。运行数据继续写入被忽略的 `output/`、`state/` 和 `logs/`，不进入提交。

本版本不改变 verified 的定义，不允许 Codex 修改 AI/科技相关性规则或官方域名/GitHub 组织白名单，不绕过登录、付费墙、robots 或验证码。

## 交付切片

### 1. 来源等级与 Run 状态

- 保留来源详细成熟度等级；`experimental` 来源显式进入 SourceHealth、SourceResult 和 report。
- `experimental` 来源的 blocked/failed 不影响 RunReport `status`；稳定来源异常仍按 complete/partial/failed 规则处理。
- 来源状态报告列出等级、角色、计数和结构化错误。

### 2. 官方 HTML Adapter

- 官方目录页按单个标题和明确发布日期输出事件；发布日期未知的条目不伪造日期。
- 没有任何可确认日期的目录页只保存 `state/source_snapshots/<source-id>.json`，不生成新闻事件。
- 官方 HTML 候选摘要最多 500 字；正文摘录仍保留给统一第一方证据复核。

### 3. 相关性与第一方证据闭环

- discovery 候选使用可测试、确定性的 AI/科技词表过滤；词表只匹配候选可读文本，URL 和 HTML 标记不计为命中；不相关候选记录 `filtered` 和原因并停止进入新闻流水线。
- 保留的 discovery 候选进入 Codex 第一方证据查找；程序继续精确校验官方域名/组织、可访问性、正文逐字摘录、日期和可见正文哈希。
- Codex 不能扩大白名单；无证据、超时、摘录/日期/哈希不匹配继续保持 `unverified`。
- RunReport 记录 `filtered`、`verification_attempted`、`no_primary_evidence` 以及稳定原因计数。

### 4. 离线 Markdown 报告

- 新增中文 `mynews report`，只读取 RunReport，不访问网络、不调用 Codex。
- 报告固定分为“已核验、待核验、价格变化、来源状态”；只展示 RunReport 已有事实、链接、原因和证据摘录。

## 契约与文档同步

- RunReport 新输出使用 schema `1.1`；新增 `SourceResult.stability`、`reason_counts` 和质量统计，旧 `1.0` fixture 仍兼容。
- SourcePlugin/SourceCollection 增加来源快照 seam；NewsStore 负责原子保存来源快照。
- 同步 ADR-0001、系统架构、来源目录、JSON 契约、功能矩阵、README 和本索引；已完成的 v1 计划归档到 `docs/archive/plan/2026/`。

## 验收门槛

| 门禁 | 要求 |
| --- | --- |
| G0/G1 | 文档索引、归档、链接和 `git diff --check` 一致 |
| G2 | `uv run ruff check .`、`uv run mypy src` |
| G3 | 受影响测试和全量测试通过；旧 v1 fixture 兼容 |
| G4/G5 | 中文 help、report 离线输出、JSON Schema、fixture、快照和失败保护 |
| G6-S | 内置来源实时 probe；实验来源失败如实保留且不影响 Run 状态 |
| G6-V | 至少一个 discovery 候选完成真实 Codex 建议和程序二次核验 |
| G7 | 隔离七天采集、跨运行去重、latest/Schema/verified 证据复核；不安装 launchd |
