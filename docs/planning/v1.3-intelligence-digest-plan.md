# mynews v1.3 情报简报计划

## 基线与边界

本计划从 `origin/main@768403924666c3e17a941b903910743f685f7fbc` 创建，分支为 `codex/v1.3-intelligence-digest`。v1.3 只读取已经保存的 RunReport 和上一期 Digest，新增独立的整理、聚合、排序、摘要和导出层；不修改来源采集、相关性过滤、`verified` 定义、第一方证据解析、pending 重试或现有 Store 事务门槛。

`verified` 仍只能来自程序核验的第一方证据。`unverified` 只能进入“线索观察”，必须显示核验原因和重试状态；任何线索文本、模型输出或摘要都不能把条目升级为事实。

## 交付范围

1. 独立 `DigestBuilder`：输入 `RunReport` 与可选上一期 `Digest`，保守聚合同一事件，按相关性 35%、热度 25%、时效 20%、事件类型 20% 确定性排序，并标记 `new`、`updated`、`ongoing`。
2. 独立 Digest Schema 1.0：主榜只包含 `verified`；线索观察只包含 `unverified`，保留原因、重试和证据引用。
3. Codex 摘要 seam：只把 RunReport 中已保存的第一方证据传给模型，严格校验返回的条目 ID、证据 URL 引用和中文摘要/影响判断；模型异常、超时、非法 JSON 或不合法引用均回退到标题与已保存证据摘录，整体状态为 `partial`。
4. 原子输出：在 `--out-dir` 下生成 `digests/<digest-id>.json`、`digest-latest.json` 和 `digest-latest.md`；历史文件与 latest 一起提交，失败恢复旧 latest，不留下临时文件。
5. 中文 `mynews digest` 参数：`--run`、`--out-dir`、`--max-items`、`--summary-model`、`--summary-timeout`、`--no-codex`。`scripts/collect.sh` 仅在显式 `--digest` 时追加简报生成，默认采集行为不变。
6. 同步系统架构、Digest 数据契约、功能矩阵、根 README、计划索引和 ADR。

## 聚合、排序与生命周期口径

- 精确 URL 或相同事件键可聚合；不同 URL 还必须同时满足相同事件类型、存在共同实体、标题高相似度和合理日期距离。仅同厂商、同类型或相似关键词不得合并。
- 时效分为 0–100，按报告完成时刻与事件时间的天数衰减；事件类型权重固定记录在数据契约中。排序使用整数化权重并以事件键作最终稳定 tie-breaker。
- 当前事件首次出现在上一期之后为 `new`；事实、证据、标题或评分发生变化为 `updated`；其余为 `ongoing`。上一期同时检查主榜和线索观察。
