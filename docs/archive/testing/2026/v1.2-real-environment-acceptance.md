# v1.2 真实环境验收与交接清单

## 执行边界

- 分支：`codex/v1.2-evidence-lifecycle`。
- 基线：`main@756997998051de22746fcd7bf9b211129697de0d`。
- 执行前必须记录实际 `HEAD`；不要把本文中的历史提交号当作最终执行提交。
- 所有运行数据写入隔离临时目录，不写仓库的 `output/`、`state/` 或 `logs/`。
- 本清单不安装、不加载、不卸载也不查询真实 launchd；launchd 仅保留既有离线测试。

## 环境前置条件

真实环境至少需要：

1. Git、Python 3.12 和 `uv` 可用。
2. `codex` 可执行文件在 `PATH` 中，且已完成真实账号认证。
3. 默认模型 `gpt-5.6-luna` 对当前账号可用；若改用其他模型，必须记录模型名和原因。
4. 能访问 Hacker News 以及候选对应的第一方官方页面；DNS、TLS、代理和防火墙不能静默改写响应。
5. 系统时间和时区正确。

执行预检：

```bash
git fetch origin
git switch codex/v1.2-evidence-lifecycle
git pull --ff-only
git status --short
git rev-parse HEAD
python3 --version
uv --version
codex --version
uv sync --all-groups
python3 scripts/check_docs.py
git diff --check origin/main...HEAD
uv run ruff check .

uv run pytest -q
```

`git status --short` 必须为空。任何离线门禁失败时先停止真实环境验收，按 `FAIL` 处理并修复，不能继续用真实运行掩盖回归。

## 隔离工作目录

在仓库根目录执行：

```bash
REPO="$(pwd -P)"
ACCEPT_ROOT="$(mktemp -d "${TMPDIR:-/tmp}/mynews-v12-real.XXXXXX")"
MYNEWS="${REPO}/.venv/bin/mynews"
mkdir -p "${ACCEPT_ROOT}/artifacts"
printf 'repo=%s\naccept_root=%s\nhead=%s\n' \
  "$REPO" "$ACCEPT_ROOT" "$(git rev-parse HEAD)" \
  > "${ACCEPT_ROOT}/artifacts/environment.txt"
cd "$ACCEPT_ROOT"
```

后续所有 `output/`、`state/` 和报告都应位于 `$ACCEPT_ROOT`。执行结束后先保留该目录用于复核；确认验收记录已经整理后再人工删除。

## G6-S：真实来源健康检查

执行：

```bash
set +e
"$MYNEWS" probe \
  > artifacts/probe.json \
  2> artifacts/probe.stderr
PROBE_RC=$?
set -e
printf 'probe_exit_code=%s\n' "$PROBE_RC" \
  >> artifacts/environment.txt
cat artifacts/probe.json
```

记录以下事实：执行日期和时区、出口网络边界、`codex --version`、probe 退出码、每个来源的 `source_id`、`stability`、`health`、计数和错误代码。

判定规则：

- `PASS`：来源返回结构化结果，受影响的稳定 discovery/官方来源能够真实访问；实验来源如实 `blocked` 可以接受。
- `PASS_WITH_LIMITATIONS`：非关键来源受外部限制，但错误被结构化记录且不影响 G6-V 使用的来源；必须逐项说明。
- `BLOCKED`：DNS、TLS、代理、权限或服务故障使 G6-V 所需的 discovery/官方来源无法运行。
- `FAIL`：未捕获异常、错误状态被伪装为 healthy、响应解析或状态聚合不符合契约。

退出码 `3` 只表示 partial，不可单独据此判定失败或通过；必须检查每个来源的结构化结果。

## G6-V：真实 Codex 与程序二次核验

选择一个明确包含 AI/科技 discovery 候选的连续七个自然日窗口。下面日期仅为示例；实际执行时可以替换，但两次运行必须使用完全相同的 `FROM` 和 `TO`：

```bash
FROM=2026-07-30
TO=2026-08-05
MODEL=gpt-5.6-luna
```

首次运行：

```bash
set +e
"$MYNEWS" collect \
  --from "$FROM" \
  --to "$TO" \
  --source hacker-news \
  --verification-model "$MODEL" \
  --verification-budget 30 \
  --verification-batch-size 1 \
  --verification-timeout 120 \
  > artifacts/run1.stdout.json \
  2> artifacts/run1.stderr
RUN1_RC=$?
set -e
printf 'run1_exit_code=%s\n' "$RUN1_RC" \
  >> artifacts/environment.txt
cp output/latest.json artifacts/run1-latest.json
"$MYNEWS" validate \
  --run artifacts/run1-latest.json \
  --check-evidence \
  --timeout 120 \
  > artifacts/run1-validate.json
"$MYNEWS" report \
  --run artifacts/run1-latest.json \
  --out artifacts/run1-report.md
```

使用以下检查确认至少一条结果确实经过生产 Codex 路径，而不是候选自身或页面直链的确定性核验：

```bash
"${REPO}/.venv/bin/python" - <<'PY'
import json
from pathlib import Path

report = json.loads(Path("artifacts/run1-latest.json").read_text())
matches = []
for item in report["items"]:
    if item.get("verification_status") != "verified":
        continue
    if item.get("verification_reason") != "codex_primary_evidence":
        continue
    if "discovery" not in item.get("source_roles", []):
        continue
    for evidence in item.get("primary_evidence", []):
        validation = evidence.get("validation", {})
        strict = (
            evidence.get("published_at") is not None
            and validation.get("reachable") is True
            and validation.get("official_domain") is True
            and validation.get("redirect_safe") is True
            and validation.get("excerpt_matched") is True
            and validation.get("date_matched") is True
            and validation.get("content_hash_matched") is True
            and validation.get("lifecycle_status") == "current"
        )
        if strict:
            matches.append(
                {
                    "event_key": item["event_key"],
                    "title": item["title_original"],
                    "candidate_url": item.get("canonical_url"),
                    "evidence_url": evidence["url"],
                    "published_at": evidence["published_at"],
                    "excerpt": evidence["excerpt"],
                    "content_hash": evidence["content_hash"],
                }
            )
assert matches, "没有真实 codex_primary_evidence 且通过完整程序校验的 discovery 条目"
Path("artifacts/g6-v-evidence.json").write_text(
    json.dumps(matches, ensure_ascii=False, indent=2) + "\n"
)
print(json.dumps(matches, ensure_ascii=False, indent=2))
PY
```

G6-V 只有同时满足以下条件才是 `PASS`：

- `verification_reason` 为 `codex_primary_evidence`。
- 来源角色包含 `discovery`。
- 第一方证据 URL、发布日期、逐字摘录和正文哈希可人工复查。
- 六项程序门槛全部为 true，生命周期为 `current`。
- `validate --check-evidence` 返回通过。

以下情况不得写成 PASS：

- `codex_unavailable`、认证失败、模型不可用、超时或网络阻断：`BLOCKED`。
- `codex_no_suggestion` 或所有建议均未通过程序复核：门禁未满足，保持 `BLOCKED`；同时记录原因计数。
- Codex 输出坏 JSON、程序崩溃、白名单或严格校验被绕过：`FAIL`。
- 只有 `official_source` 或页面直链核验成功，没有 `codex_primary_evidence`：不计入 G6-V。

## G7：同一窗口连续两次七天运行

第二次运行必须继续使用同一个 `$ACCEPT_ROOT`、`FROM`、`TO` 和模型配置。默认 pending 重试延迟为零，因此第一次产生的到期 pending 可以在第二次运行立即重试。

```bash
set +e
"$MYNEWS" collect \
  --from "$FROM" \
  --to "$TO" \
  --source hacker-news \
  --verification-model "$MODEL" \
  --verification-budget 30 \
  --verification-batch-size 1 \
  --verification-timeout 120 \
  > artifacts/run2.stdout.json \
  2> artifacts/run2.stderr
RUN2_RC=$?
set -e
printf 'run2_exit_code=%s\n' "$RUN2_RC" \
  >> artifacts/environment.txt
cp output/latest.json artifacts/run2-latest.json
"$MYNEWS" validate \
  --run artifacts/run2-latest.json \
  --check-evidence \
  --timeout 120 \
  > artifacts/run2-validate.json
"$MYNEWS" report \
  --run artifacts/run2-latest.json \
  --out artifacts/run2-report.md
```

执行结构检查：

```bash
"${REPO}/.venv/bin/python" - <<'PY'
import json
from pathlib import Path

root = Path(".")
runs = sorted((root / "output/runs").glob("*.json"))
assert len(runs) == 2, f"期望 2 个历史 run，实际 {len(runs)}"
assert (root / "output/latest.json").exists()
assert (root / "state/dedup.json").exists()
assert (root / "state/pending_verifications.json").exists()
run1 = json.loads((root / "artifacts/run1-latest.json").read_text())
run2 = json.loads((root / "artifacts/run2-latest.json").read_text())
latest = json.loads((root / "output/latest.json").read_text())
assert run1["run_id"] != run2["run_id"]
assert latest["run_id"] == run2["run_id"]
assert run1["schema_version"] == "1.2"
assert run2["schema_version"] == "1.2"
summary = {
    "run_count": len(runs),
    "run1": {
        "run_id": run1["run_id"],
        "status": run1["status"],
        "stats": run1["stats"],
        "verification_stats": run1["verification_stats"],
    },
    "run2": {
        "run_id": run2["run_id"],
        "status": run2["status"],
        "stats": run2["stats"],
        "verification_stats": run2["verification_stats"],
    },
}
Path("artifacts/g7-summary.json").write_text(
    json.dumps(summary, ensure_ascii=False, indent=2) + "\n"
)
print(json.dumps(summary, ensure_ascii=False, indent=2))
PY
```

G7 通过条件：

- 两次运行使用相同七天窗口并产生两个不同历史 run。
- `latest.json` 指向第二次 complete 或 partial 运行。
- `dedup.json` 和 `pending_verifications.json` 均可读取。
- 第二次运行如存在第一次 pending，应在 `verification_stats.retried` 中体现；成功后对应 pending 消失，失败则尝试次数和原因按规则演进。
- 第二次运行中的重复新闻不应作为新事件重复输出；`deduplicated_count` 与实际状态一致。
- 两次 RunReport 都通过 Schema 校验、证据复核和离线 report 生成。
- 运行目录中没有残留 `.*.tmp` 文件。
- 仓库工作树仍然干净，仓库内没有新增 `output/`、`state/` 或 `logs/` 跟踪内容。

若第一次没有产生 pending，不能伪造 `retried > 0`；如实记录“本次真实样本未覆盖 pending 重试”，并将 pending 真实重试项标为 `SKIPPED` 或另选包含可重试失败的窗口继续执行。自动化测试已覆盖状态机，但不能替代这一真实样本说明。
