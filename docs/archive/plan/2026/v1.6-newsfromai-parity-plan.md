# mynews v1.6 newsFromAI 数据能力完整吸收计划

## 目标与范围

本计划从最新 `main` 提交 `1d32de2` 开始；实施时必须从包含该提交的最新
`main` HEAD 创建新的 `codex/v1.6-newsfromai-parity` 分支，不得从 v1.5 实施分支续做。

目标是完整吸收 `/Users/edgarlqs/Downloads/newsFromAI` 当前
`datacollection` 主线的确定性数据能力：来源配置、业务日期与 freshness、正文增强、
历史观察、保守去重、候选契约和 editorial pack。新闻价值判断、第一方事实核验和
作者终审继续使用 mynews 已有边界。

## 已吸收与待吸收

v1.5 已吸收 SourcePlugin、15 个扩展来源、来源角色、基础人工清单、输出隐私门禁、
失败隔离和 report 原子写入。newsFromAI 当前配置仍有 17 个自动 Feed 和约 65 个
`manual_watchlist` 项；mynews 目前只覆盖其中的自动来源映射和 9 个基础人工项。

本阶段必须补齐：

- 所有当前配置项的 source/manual inventory 和重复映射关系；
- 业务日期当天及前一天的 freshness 过滤、稳定重放和 `--refresh`；
- RSS/Atom/HTML 正文清理、元数据增强、长度上限和失败状态；
- first-seen 精度、来源族、重复观察、保守跨来源事件分组；
- Candidate Contract v1、JSON Schema、候选成员匹配统计和兼容读取；
- `candidates.json`、`candidates.md` 和人工 editorial pack；
- 完整人工检查清单、publication history 和 weekly feedback 的只读提示能力。

## 架构决定与非目标

- 继续使用 mynews 的 SourcePlugin、RunReport、JSON Store、DedupState、EvidenceVerifier
  和 Digest；不得引入第二套事实来源。
- newsFromAI 的 SQLite 只吸收其事实/观察语义，不复制 SQLite 实现；如需改变此决定，
  必须另立 ADR 和范围计划。
- `prepare` 只组合采集、候选导出和 editorial pack，不调用 Codex、不自动发布。
- X 账号、无稳定 RSS 的页面、论文和评测只进入人工清单，不自动抓取。
- Web/UI、自动发布、PPT、Canva、视频、TTS、MCP 和定时内容生产不属于本阶段。
- 不降低第一方 evidence/verified 门槛，不绕过登录、付费墙、robots、验证码或访问控制。

## 公共接口与输出

新增稳定命令：

```bash
mynews prepare --date YYYY-MM-DD
mynews prepare --date YYYY-MM-DD --refresh
```

输出目录：

```text
output/editorial/YYYY-MM-DD/candidates.json
output/editorial/YYYY-MM-DD/candidates.md
```

Candidate Contract v1 至少包含 `schemaVersion`、`date`、`generatedAt`、`stats`、
`candidateRef`、`idScope`、`match`、`sourceRole`、`firstSeenAt`、`firstSeenPrecision`、
`duplicateGroupId`、`multiSources`、`evidence` 和可选 `publicationHistory`。候选最多
500 条，且必须满足 `firstSeenAt <= generatedAt`。输出失败不得修改 Store 或输入文件。

## 验收门槛

首轮必须只读，覆盖目标分支与 `main` merge-base 的提交、未提交和未跟踪文件。按变更
类型执行 G0、G1、G2、G3、G4、G5、G6-S；只有声明发布候选时再增加 G7。

必须验证：

1. 配置覆盖率为 100%；重复来源只能复用 built-in，不能产生第二个事实来源。
2. 每个自动来源都有 fixture、entry-point/registry、失败测试和真实 probe；人工来源必须
   是 `manual_source` 或 `blocked`，不能伪装成健康 Feed。
3. 日期过滤、refresh、稳定重放、正文清理、字段上限和不可信网页输入边界通过。
4. 同 URL/同事件去重、跨来源保守聚类、first-seen、source family 和历史提示通过。
5. Candidate JSON Schema、Markdown、统计、最多 500 条、隐私检查和原子失败恢复通过。
6. 普通 collect/probe、`--plugin`、`--with-plugin`、watchlist 和 digest 无回归。
7. 真实网络或 Codex 阻断写 `BLOCKED`/`SKIPPED`；fixture/mock 只能证明 Implemented。

## 完成定义与后续工作

P0–P7 完成并通过复验后，newsFromAI 当前 `datacollection` 能力在 mynews 中完成吸收，
不再有本主题的预定功能阶段。之后只保留：来源健康复验、manual watchlist 维护、依赖
升级、真实 Codex/G7 复验和新的用户需求；这些属于运行维护或新计划，不回写为本阶段缺陷。
