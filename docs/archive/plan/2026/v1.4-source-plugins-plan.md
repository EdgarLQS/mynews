# mynews v1.4 外部来源插件计划

## 基线与边界

本计划从 v1.3 完成提交 `5b44183` 创建，目标分支为
`codex/v1.4-source-plugins`。v1.3 情报简报计划已按 Implemented 归档；其中真实
Digest Codex 验收仍为 `BLOCKED`，原文保留在
`docs/archive/plan/2026/v1.3-intelligence-digest-plan.md`。

v1.4 只扩展来源加载控制，不改变 SourcePlugin API 1.0、内置 registry 的顺序和
行为、第一方证据门槛、核验器、Digest、RunReport 1.x 或 Store 事务语义。不新增
正式内置来源；Hacker News 或官方来源只在隔离临时分发包中用于协议验证。

## 交付范围

1. 新增 Python entry-point group `mynews.source_plugins` 的发现和加载器。
   entry-point 名称是 `--plugin <id>` 使用的 ID；其 value 必须解析为无参数工厂，
   工厂返回实现 SourcePlugin 1.0 的对象。
2. 加载前严格校验 SourcePlugin、SourceMetadata、`source_id`、`plugin_api_version`、
   `role`、`official_domains`、`capabilities`、HTTPS homepage 和方法返回边界。
   外部 source_id 必须唯一，且不能与内置来源冲突。
3. 外部来源只在显式 `--plugin` 下加载。普通 `collect`、普通 `probe` 和
   `plugin list` 不执行外部工厂；`plugin list` 只发现并列出 entry-point 元数据。
4. 新增中文命令：`plugin list`、`plugin probe --plugin <id>`，并为既有
   `collect`、`probe` 增加 `--plugin <id>` 选择。插件返回候选、SourceBatch 或
   SourceHealth，不能进入 Store、Codex、Verifier 或修改 verified 状态。
5. 加载失败、重复 ID、协议不兼容、工厂异常和来源运行时异常均输出稳定结构化
   错误。加载失败不启动流水线；来源失败沿用现有 failed Run 保护，不覆盖
   latest、dedup、pending 或已有历史 run。
6. 外部插件是受信任的本地 Python 代码。显式允许清单只控制发现后是否加载，
   不承诺进程级沙箱；插件不得绕过访问控制或第一方证据规则。

## 兼容规则

- `SourcePlugin` 1.0 和 `SourceMetadata.plugin_api_version == "1.0"` 保持不变。
- 不带 `--plugin` 的 collect/probe 与 v1.3 相同，只使用 built-in registry。
- RunReport 仍输出 1.2，旧 1.0/1.1/1.2 读取规则不变；插件健康结果复用既有
  SourceResult 结构，不增加持久化插件字段。
- `--source` 与 `--plugin` 互斥；显式插件选择会把加载后的 metadata.source_id
  写入 requested_range.source_ids。

## 离线验收门槛

| 门禁 | 要求 |
| --- | --- |
| P1 | 未显式允许时不加载工厂；内置 registry 顺序和既有选择回归通过 |
| P2 | 正常发现、显式加载、plugin list/probe、collect/probe 和 source selection 通过 |
| P3 | 元数据、协议版本、空 capabilities、重复 source_id、内置冲突和工厂失败通过 |
| P4 | 插件 collect/probe 异常、来源失败和 failed Store 保护通过 |
| P5 | 隔离临时分发包真实 entry-point 发现通过；不修改正式来源目录 |
| P6 | 中文 help、非法参数、退出码、既有 RunReport 兼容性、文档检查、Ruff、mypy 和全量测试通过 |

离线门禁最高只能把能力标为 `Implemented`。真实网络、真实 Codex、launchd 和
进程级安全隔离不属于本计划的 Verified 证据；不得操作真实 launchd，也不得提交
`output/`、`state/`、`logs/`。
